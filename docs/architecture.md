# 架构与维护

系统将离线解析、配置采集、语义解释和业务运行分析分开维护。

1. 流程和建模解析器读取导出文件，保留证据和未知状态。
2. 基础数据工具按登记来源采集B01—B09，生成不可覆盖批次及人工审核记录。
3. 审查逻辑核对字段、物理模型、节点、规则、取人、布局、权限和自动行为。
4. 部署方为具体流程编写最小字段读取和本地对账规则；原始敏感值留在本地。
5. AI基于经过投影的配置结构或批准计数解释问题，给出原因、业务影响、改法与验收。
6. 配置与数据证据、实际岗位测试和接口运行结果分别记录。

## 基础数据分类

| 编号 | 内容 |
| --- | --- |
| B01 | 流程目录与版本定义 |
| B02 | 表单字段、选项、物理主明细结构 |
| B03 | 节点、路径、规则与拓扑 |
| B04 | 操作人、组织引用、基础字段权限 |
| B05 | 布局、公式、带入、联动、动作、编号与超时 |
| B06 | 关联建模、浏览框及字段关系 |
| B07 | 报表、查询列表、共享及虚拟表来源 |
| B08 | 接口定义、触发位置及明确源码证据 |
| B09 | 运行记录的数据结构及明确代码参考 |

## 扩展流程

先登记来源、范围、字段、参数、分页、限额、超时、关联键及失败处理，再实现读取与合成测试。使用新的批次目录保存读取方法版本、输入输出哈希、差异和人工审核。

同一个字段可由人工、公式、联动、节点动作、脚本或接口赋值。分别保存来源和触发时机，在对应环境验证有效权限、执行顺序及持久化结果。

报表以业务对象的稳定主键确定粒度；多条反馈和发货记录先按明确规则关联或聚合。完成、取消、失败、待补偿分别管理，避免用单一“归档”或“成功”概括全部业务状态。

## 迁移

代码和通用方法随仓库迁移。本地连接、源码根目录与企业数据单独迁移；DPAPI凭据在目标机器重新初始化。源码参考使用config中的模板登记具体文件，不扫描任意文件夹，也不把源码存在当作已部署证明。
