# OA流程质量审查清单 v2.0（公开版）

## 1. 审查输入

| 输入 | 最低内容 |
|---|---|
| 业务基线 | 适用场景、审批职责、分支条件、完成定义、例外规则、验收标准 |
| 流程配置 | 流程节点、连线、审批人解析、退回/结束条件、版本 |
| 表单配置 | 字段ID/类型、必填、显隐、读写、默认值、明细与附件 |
| 权限配置 | 角色及组织映射、节点读写权限、关联单据权限 |
| 扩展配置（适用时） | 脚本、定时器、外部接口、映射、调用与重试机制 |
| 测试证据 | 测试场景、测试账号角色、输入、预期与实际、运行日志 |

## 2. 判定与放行标准

- **P0**：必要审批、关键权限、关键数据或业务完成条件方面的阻断风险。已证实不合格时禁止上线。
- **P1**：应修复；确需带风险上线时须有授权人员批准和记录。
- **P2**：非阻断性的使用效率与易用性问题。
- **PASS**：全部所需证据充分，且满足本项合格判据；静态配置不能替代运行验证。
- **FAIL**：存在可定位的配置反例或失败测试，能证明违反规则。
- **待业务确认**：业务预期未获确认，无法判定配置是否符合业务。
- **无法验证**：缺少配置、执行日志、测试结果等必要证据。
- **不适用**：不涉及该功能或场景，需说明原因。
- **BLOCK**：存在P0 FAIL；**HOLD**：关键检查或强制测试未完成，或P1 FAIL未经处理；**CONDITIONAL**：仅剩已授权接受的P1风险；**READY**：适用P0/P1通过且规定测试与业务验收完成。

## 3. 逐项检查

每一项按照“适用性 → 合格判据 → 核验证据 → 记录结论”的顺序执行，检查对象在配置中必须定位到节点、字段、连线、表达式或接口事件。表中“验证依据”中的「配置」指可读取的导出配置；「业务基线」指已确认的业务规则；「运行测试」指有结果及日志的实际测试。


### 01. 需求与业务规则

| 编号 | 级别 | 检查项 | 合格判据 | 验证动作 | 验证依据 |
|---|---|---|---|---|---|
| BR-01 | P0 | 有可核对的业务依据 | 存在已确认的流程目的、发起条件、适用业务范围、输入输出、责任人及完成定义；缺失则不得宣称业务审查通过。 | 核对流程适用与不适用场景，确认发起条件和完成条件 | 业务基线 |
| BR-02 | P0 | 业务情形覆盖 | 所有已确认业务类型、公司、工厂、单据类别都有相应路径；未匹配类型有明确阻止/兜底机制。 | 覆盖所有业务类型、组织维度、空值及未知类型 | 配置+业务基线 |
| BR-03 | P1 | 审批职责和职责分离 | 各必要审批、复核、执行与会签责任明确；职责分离限制和允许的例外均有业务授权依据。 | 检查同一人同时发起与审批时是否违反职责分离规则 | 业务基线 |
| BR-04 | P0 | 合法例外不被错误阻断 | 必填、关联单据和前置审批只对需满足的业务类型生效；合法替代路径不会被通用规则阻断。 | 验证允许不提供某前置资料的合法例外是否能够提交 | 配置+业务基线 |
| BR-05 | P1 | 业务事实与数据粒度一致 | 一个单据包含多条独立业务明细时，可独立取值的属性按明细记录；仅确实共享的属性放在表头。 | 一张单据多条明细存在不同属性值时能否分别保存与审批 | 业务基线 |
| BR-06 | P1 | 系统边界不重复审批 | 明确跨系统的控制责任、主数据来源与校验边界；无未经确认的重复审批或必要控制缺口。 | 核对已有其他系统审核的事项是否重复审批或遗漏控制 | 配置+业务基线 |
| BR-07 | P1 | 流程结束不等于业务未完成 | 明确“审批通过、数据过账、附件补齐、外部系统完成”的各自完成条件；未满足业务完成定义不能错误显示已完成。 | 审批完成但业务交付未完成时，核对流程完成状态 | 业务基线 |

### 02. 节点与路由

|---|---|---|---|---|---|

| WF-03 | P0 | 分支条件完整且不冲突 | 每个网关分支条件明确定义，互斥或明确多分支策略，覆盖所有合法值，并有未匹配的异常处理。 | 分别输入空值、未定义枚举和各阈值边界，检查命中分支 | 配置 |
| WF-04 | P0 | 路由与岗位职责一致 | 每个业务条件路由到经业务确认的岗位、公司、工厂及审批层级；不得因默认人设置误流转。 | 切换公司、部门、业务类型和金额区间核对审批岗位 | 配置+业务基线 |
| WF-05 | P1 | 节点可达且无意外死路 | 预期节点可达；每条合法路径可正常结束或进入明确的异常处理；允许回退但不得存在无退出条件的循环。 | 遍历全部节点与连线，检查孤立节点、意外死路和无退出条件循环 | 配置 |
| WF-06 | P0 | 退回、驳回、撤回后的状态一致 | 业务规则规定的退回目标、重提后审批顺序及数据保留方式正确；不可绕过必要复核。 | 退回后更改关键字段重新提交，检查是否重新执行必要审批 | 业务基线+运行测试 |
| WF-07 | P1 | 并行与会签完成条件明确 | 会签通过人数、全部通过、任一否决、超时及任务合并规则明确定义，不会过早结束或永久等待。 | 模拟会签中的拒绝、超时、人员缺失与部分通过 | 配置+运行测试 |
| WF-08 | P1 | 审批人动态解析可复现 | 按组织、岗位、表单字段等动态计算处理人时，有合法数据来源、解析记录与空值兜底。 | 变更组织或单据关键字段，检查处理人解析结果及异常兜底 | 配置+运行测试 |
| WF-09 | P1 | 代理与转办授权清楚 | 代办、转办、加签、会签、委托的触发条件、权限和审计责任明确；关键审批不可任意转给无权限人。 | 模拟委托、代理、转办操作，检查越权与记录完整性 | 业务基线+运行测试 |
| WF-10 | P0 | 结束与归档触发正确 | 仅在业务要求的审批、执行及外部动作达到完成条件后结束或归档；人员缺失不会导致提前结束。 | 跳过非必要节点及人员缺失场景下，验证归档条件 | 配置+运行测试 |
| WF-11 | P1 | 归档人/抄送人/责任人不混淆 | 归档责任、抄送对象、处理人以及创建人是独立规则；按业务类型明确并配置，不以抄送代替归档。 | 按业务类型核对归档、执行、审批及抄送对象的独立配置 | 配置+业务基线 |

### 03. 表单与字段

| 编号 | 级别 | 检查项 | 合格判据 | 验证动作 | 验证依据 |
|---|---|---|---|---|---|
| FM-01 | P0 | 关键字段类型和含义一致 | 金额、数量、日期、枚举、人员、公司、工厂、料号类型正确；字典值与业务含义一致。 | 输入非法字段类型、未知字典值、无效日期或编号 | 配置+业务基线 |
| FM-02 | P0 | 必填条件按节点与场景生效 | 必填字段必须在负责填写的节点可编辑且实际可提供；可选业务不能因不适用字段被阻断。 | 切换必填适用条件，检查合法例外是否可保存和提交 | 配置+业务基线 |
| FM-03 | P1 | 显示/隐藏与必填联动 | 字段被隐藏/只读时不会被强制要求本节点填写；条件改变后字段显示和校验同步更新。 | 字段隐藏或只读时，检查是否仍错误触发必填校验 | 配置+运行测试 |

| FM-05 | P1 | 表头明细一致且可多行 | 一行一实体的字段位于明细层；多行新增、删除、复制、排序时逻辑与合计一致。 | 测试多明细新增、删除、复制及跨行差异值与汇总 | 配置+业务基线 |
| FM-06 | P1 | 字段精度/汇总/边界正确 | 数量与金额按业务定义控制小数、非负、上限、单位与合计；显示格式不造成精度或货币误读。 | 测试零值、负数、精度边界、上下限、汇总与单位换算 | 配置+运行测试 |
| FM-07 | P0 | 修改后历史与重提数据正确 | 保存、退回、撤回与重新提交后字段值及附件按规则保留；关键字段变化会触发必要的派生值及审批路由重算。 | 保存、退回、修改并重提，核对字段留存和派生值重算 | 业务基线+运行测试 |
| FM-08 | P1 | 动态取数有效且有失败提示 | 自动取数失败时不得以错误值或过期值静默覆盖表单；有可识别提示和恢复路径。 | 模拟数据源为空、无权限、超时和错误响应 | 配置+运行测试 |
| FM-09 | P1 | 附件要求具体且可验证 | 附件是否必传、何节点上传、格式/数量、审批人需要查看哪些内容明确；只校验上传不代表内容被批准。 | 模拟缺附件、附件不可读和附件内容待核验的场景 | 配置+业务基线 |
| FM-10 | P1 | 字段修改权限责任明确 | 每个关键字段由哪个节点填写/修改、哪个节点审核明确；避免申请人或后续节点不当修改已审批数据。 | 使用不同角色尝试修改已审批关键字段 | 业务基线 |

|---|---|---|---|---|---|
| CH-01 | P0 | 变更不会破坏在途实例 | 识别受影响的在途实例，明确旧版继续运行、迁移或重启策略；关键路径经回归测试验证。 | 取一个变更前的在途实例，验证变更后处理与版本策略 | 配置+运行测试 |
| CH-02 | P1 | 变更经过适当业务审批 | 影响路由、岗位、权限、数据校验或外部写入的变更，有授权业务负责人的确认和版本记录。 | 检查影响审批权责、字段必填和接口行为的变更确认记录 | 业务基线 |
| CH-03 | P1 | 历史数据兼容新字段 | 新字段、枚举和默认值变更时，老实例不会因必填/计算新增规则卡住；旧报表/数据映射兼容。 | 用旧版本实例运行到新增必填或新字典值节点 | 配置+运行测试 |
| CH-04 | P0 | 管理员修复可回放与审计 | 如强制归档、数据库直改、批量节点调整，需有审批、变更单、影响清单、备份和操作结果验证。 | 检查管理员修复审批、影响范围、备份、日志和结果验证 | 配置+运行测试 |
| CH-05 | P1 | 测试、正式环境版本一致 | 流程定义、脚本、角色、字典、接口地址和定时任务有版本/配置对比；避免只部署部分配置。 | 对比测试与正式环境的流程、脚本、字典、角色和接口映射 | 配置+运行测试 |
| CH-06 | P1 | 上线回退和失败恢复方案明确 | 针对错误路由、误通知、接口重复写入等上线事故，具备暂停、回退、补救和通知责任人的步骤。 | 模拟上线故障，检查暂停、回退及数据纠正步骤 | 配置+运行测试 |
| CH-07 | P1 | 业务台账及报表口径一致 | 流程状态、归档结果与报表统计口径一致；不会因配置变更让历史报表、证书台账、待办数量对不上。 | 对账不同状态的单据及历史报表统计口径 | 业务基线+运行测试 |

### 08. 测试与可审计性

| 编号 | 级别 | 检查项 | 合格判据 | 验证动作 | 验证依据 |
|---|---|---|---|---|---|
| QA-01 | P0 | 每条业务分支有测试用例 | 每条有效分支至少一个正向测试用例；关键条件及高风险拒绝路径有异常、边界用例，且测试结果可追溯。 | 为每条有效分支生成正常用例，为关键条件生成异常和边界用例 | 配置+运行测试 |
| QA-02 | P0 | 关键拒绝路径测试通过 | 缺少关键审批人、非法权限、必填缺失、外部失败等情况应失败且不可绕过。 | 执行缺审批人、无权限、缺必填、接口失败等拒绝场景 | 配置+运行测试 |
| QA-03 | P1 | 跨角色端到端实际试跑 | 按申请人、审批人、执行人、归档人身份试跑，不仅在管理员账号下测试；截图或日志可复核。 | 分别以申请、审批、执行及归档实际角色完成全流程 | 运行测试 |
| QA-04 | P1 | 日志可解释每次决策 | 能追溯节点进出时间、选择的分支、人员解析结果、字段变更、通知、接口调用、管理员操作。 | 抽查异常跳转、改值、转办及接口失败的可追踪记录 | 配置+运行测试 |
| QA-05 | P1 | 性能和可用性压力合理 | 以经确认的数据量、附件规模及并发指标执行测试，响应时间与失败恢复达到约定验收阈值。 | 以业务约定的明细量、附件量和并发量测试性能与恢复 | 运行测试 |
| QA-06 | P0 | 业务验收口径明确 | 关键业务场景均有可检验的预期结果、验收责任人与确认记录；仅能提交或归档不代表业务验收通过。 | 核对全部关键业务场景的验收标准及确认记录 | 业务基线 |

## 4. AI审查报告最低输出字段

| 字段 | 要求 |
|---|---|
| rule_id / severity / status | 规则编号、级别、五类结论之一 |
| target | 流程ID、节点ID、字段ID、脚本路径或接口事件 |
| evidence | 配置文件路径与字段值；或测试用例、日志与执行结果的精确位置 |
| expected / actual | 已确认的期望行为与当前配置/测试结果 |
| defect / impact | 违反的具体规则及可触发的后果；无缺陷时留空 |
| correction / retest | 修复要求及可执行的复测场景 |
| gap | 待确认的业务问题或缺失证据；不适用时说明原因 |

规则库输出必须包含所有62项，且每项必须有状态；没有证据的检查不得判为PASS。缺少业务规则时，不得将猜测的业务要求作为FAIL依据。缺少运行测试时，不得报告“动态验证通过”。
