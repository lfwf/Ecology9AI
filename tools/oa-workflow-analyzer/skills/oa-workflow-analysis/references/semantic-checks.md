# OA配置语义核对要点

不同OA版本和配置表可能采用相反的枚举约定。先看 `analyzer.profile`、标准值、`raw` 与 `source_refs`，再用用户提供的同版本数据字典、配置页源码或配置导出复核。通用解析器未覆盖或与这些资料冲突时，保留原始结果，在独立补证中记录人工解释及依据；不要静默改写结果包或让旧标准值覆盖更直接的证据。

以下是在部分E9导出及配套本地资料核对中遇到的易错关系，是检查线索，不能无条件套用到其他版本：

| 项目 | 核对方法 |
| --- | --- |
| 布局用途 | 某些实现的 `workflow_nodehtmllayout.type=0/1/2` 分别是编辑／打印／移动；若解析器把打印标成移动，依据同版本定义另存纠正。用途和 `isactive` 是两个维度 |
| Action启用 | 某些配置页对 `workflowactionset.isused` 采用0启用、1停用的反向解释；不能套用其他表的同名开关。外层Action与内部建模 `isenable` 还须分别核对 |
| 节点操作人 | 某些实现的 `type=40` 引用选定节点的操作者本人，并不表示其经理；历史轮次、代理及 `level_n` 需要额外证据，不能靠名称解释 |
| 会签与抄送 | 对 `signorder` 等编码先核版本；已确认会签后，仍需结合取人结果判断人数。抄送且无需提交不能写成审批或顺序签核 |
| 路径条件 | 同时检查旧 `condition`、`newrule`、`newconditioncn` 及规则表。旧条件空但新规则存在，不是无条件出口 |
| 联动 | 保留 `isbelong`、条件关系及存储属性码；不要把联动存储码当作 `WfForm` 运行时属性码 |
| 字段权限 | 记录缺失、记录存在而原值空白、标准解析为不可见、模板未布置、只读及隐藏分别说明。明细组允许增删不证明列可维护，也不证明页面必定出现按钮 |
| 启用与超时 | 数据带入、Action、超时及其他表的0／1含义不可互套。原生超时口径不能套用另一个报表的工作时间函数 |

源码仅证明本地实现。若用户提供了接口类、服务层或配置页，可以定向关联：入口→调用→参数→业务返回→本地回写→流程返回，并记录来源、版本或哈希；不能因找到类文件或注册项就宣布已部署或实际调用成功。

同一业务中文名可对应主表与明细、不同阶段的多个字段。尤其注意明细脚本将主表字段编号拼接明细后缀的情况：这能证明引用不匹配，不证明已经读写到了主表值。行索引应按平台实际返回值核对，不默认删除后仍连续。

相似名称的成本项、人员项、日期项按所属表、节点权限、公式及实际取人区分。注释与代码、公式输入与触发项不一致时保留差异，不能只复述注释。没有计算式时写“本次导出未见”，不要写“没有计算”“完全手工”或直接发明算法。
