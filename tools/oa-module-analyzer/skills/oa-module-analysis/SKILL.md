# OA建模模块分析

把模块导出还原为一份中文模块说明书，包含功能、使用方式、实际配置及有依据的问题和优化方向。模块名、字段、数量、权限和结论均来自当前文件，不能套用示例模块。

## 离线解析

使用本skill内的 `scripts/analyze_module.py`。开发副本未内置脚本时，在用户指定位置或当前工作区的 `tools/oa-module-analyzer` 查找；不能依赖作者电脑路径。需要Python 3.10+与lxml，缺依赖时说明实际错误，可用 `python -m pip install lxml` 安装到当前任务环境。

```powershell
$env:PYTHONUTF8='1'
python '技能目录\scripts\analyze_module.py' 'C:\OA导出\模块.zip' --output 'C:\OA分析\模块结果'
```

显式传入绝对输出目录，结果另存，不覆盖输入或已有人工文档。先看CLI摘要，再读取module.json的归一化概览，按问题追到具体区段和evidence.json的成员、XML行、路径。原值、空值、空表、未导出、外部UUID引用及修改覆盖文件分别保留。表清单不是业务数据，空dataForm不证明数据库没有记录。完整取证与语义规则见[模块分析要点](references/module-analysis-guide.md)。

大JSON与长布局按问题分段读取，不整份输出进上下文。保留输入SHA-256、包内版本、解析版本和运行验证边界。Base64解码只是阅读；不执行SQL、JavaScript、类、导入器或文件内URL，不实际导入模块。

## 还原和分析

从数据产生、使用和维护责任出发，核对字段及中文选项、主明细表、创建/查看/编辑模板、列表与查询、按钮及多层启用、数据权限、导入导出、公式联动、同步与外部依赖。未导出或语义未知的内容明确保留，不从名称推断生效或权限。

业务正文和图表用中文含义。字段ID、表名、配置码、XML定位和源码指纹留在维护底稿；阅读所需来源说明放同一本说明书附录。字段名像姓名、部门或月份，不证明它已和人事、组织或日期类型关联。

分析结论放在前部，按实际业务问题合并事实、可能影响和具体改法，必要时说明责任角色、优先顺序与验收场景。质量清单用于查漏补缺，无关项跳过；不默认生成逐项审查、固定问题数、评分或独立审查报告。

“条件必填＋禁止手改”可用于自动带出后的兜底控制，应先追查赋值来源、条件、触发及失败处理。只有有证据的衔接不一致才提出修正；不能把正常设计直接判作缺陷。源代码仅证明该本地版本，存在、注册、启用、实际加载和执行成功是不同结论。

没有实例数据或执行日志时仍完成静态分析，不宣布已漏算、越权、丢失记录或节省多少时间。涉及考勤、金额等计算时，描述导出或源码表达式及口径差异，不将字段名称当算法或法定标准。

## 新增表的数据字典

需要新增流程表单或建模表字典时，读[动态数据字典导出方案](references/dictionary-export.md)。合并SQL Server实际物理元数据与OA配置中文语义，区分数据库实际结构、OA声明类型、字段标签和逻辑关联。没有直连授权时，只交付只读SQL或使用用户授权的只读接口，不连接数据库。

只看到静态字典或模块包，不能认定已取得生产DDL、索引、主外键和数据规模。字段中文注释可能未写入数据库扩展属性，应另从OA配置映射；元数据可见范围受权限限制，未返回不等于不存在。

## 交付

默认交付一份完整模块说明书；生成源、结构化证据和技术底稿供维护，不作为另一套必读报告。核对全部业务字段、选项、模板、列表与操作是否覆盖，检查建议未写成现状、未知未写成事故。按用户格式生成文档；PDF须用可用的PDF工具渲染并逐页核对。没有排版依赖时保留可用源稿，准确说明未生成的格式。

分享包仅包含通用技能、解析器和公开导出方法，不包含企业ZIP、考勤数据、人员名单、源码或分析报告；分发文件保持小于3,000,000字节。
